# C1/0.1: long feature and review exchange

The authoritative input is an explicitly identified REQUIREMENT, SOLUTION, STATUS, TASKS, task detail set, and declared gists. `source_scope` combines environment, project/feature identity, and document source ref; a local path or bare task ID is insufficient. Keep each point's original text, class, state, decision source/time, and history. A proposed point remains proposed. A task has one index row and detail, type/state/dependencies/owner/times/repository refs/point selectors. `READY` is derived, never stored as a task state. Working, integration opponent, and final PR refs have separate roles and literal full SHAs.

Review reports name report ID, attempt, reviewer, target repository and SHA, scope, source refs, and independent context. Each check has `check_id`, requirement or case, result, evidence, finding IDs, and reason. Results are `PASS`, `FAIL`, `UNKNOWN`, `NOT-RUN`, or `N/A`; `N/A` needs a reason. `ALL` counts every non-`N/A` check; `PASS` counts only `PASS`. `ALL=0` cannot be assessed. Findings have report scoped IDs, P0/P1/P2 severity, evidence, affected scope, resolution, and a current candidate recheck ref for closure. Within one report and attempt, duplicate finding IDs are one finding; across reports they need explicit origin/duplicate evidence rather than a matching bare number.

Finishing a REVIEW task means its fixed candidate report exists. Open blocking findings still prevent ACCEPT and Gate. REWORK may depend on that completed report, followed by new TEST and independent REVIEW. A report does not itself decide a requirement or close an issue. A comment's Basis identifies exact source, selector, original selected text, optional proposal, side and read line span; it grants no decision authority.

The static sequences `C1-01` through `C1-04` cover report done with blocking finding and rework ready, duplicate task ID, declared missing evidence, and stale target SHA. The fixture checker requires evidence refs for each applicable check and finding, validates their declared file, computes PASS/ALL and per-severity deduplicated finding counts, and compares those counts with the case expectation. Markdown parsing and real repository ancestry stay with the existing long feature helper; quote and code block text must never create control fields.
