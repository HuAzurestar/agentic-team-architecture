# C2/0.1: source and content conditioned access

`ref` is a provider binding ID and stable document ID, not a path or task ID. `source_key` compares current routing, scope, and mapping, but is not a persistent version. A read returns exact content, source key, actual capabilities and optional native provider condition. A write checks the source key and the expected original content against the real target under the controlled lock; remote backends need genuine native conditional writes. No safe condition means read only access or an explicitly separate copy.

An unnumbered locator may be read without index mutation. Explicit register and save also requires `expected_index` and authorization. Create requires the parent and an absent target; delete and update require exact ref, source and content; preview fixes selector and replacement, while apply consumes a short lived preview ID. A focus apply may keep edits outside an unchanged selected span; a changed span or invalidated preview is rejected. The stable document number is identity, not a revision. There is no operation journal, receipt database, or implicit retry.

Local controlled writes observe configuration, root index, then document locks, rechecking routing and content inside the lock. Config writes compare the current complete nonsecret config inside their lock. A rebind cannot occur between check and save for a controlled operation. External editors and unsafe network filesystems are outside this guarantee. File and index writes are not one transaction: a partial create reports known effects and requires explicit inspection before retry. A lost response yields `unknown` and preserves the draft. Refreshing proves current content, not that a particular attempt wrote it.

`C2-01` through `C2-10` cover changed source, competing config writers, controlled rebind, lost response, nonselected and selected preview changes, missing safe write capability, remapped ID, partial create, and changed pagination mapping. The fixture checker models the stated event result; it is not a two process locking or backend test.
