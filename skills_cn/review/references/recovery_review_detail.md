# 弱审：recovery

可制作短失败表：失败点、当前行为、恢复、风险及证据。无触发依据的猜测不计 finding。

- 每个 DB/文件/网络/外部服务失败会怎样？
- 半写文件和中断事务是否安全、可检测？
- 远端成功本地失败、或本地成功远端失败，是否明确部分成功并可恢复？
- timeout 后是否区分失败和未知成功再重试？
- 重试是否有界、去重或能协调副作用？
- restart/resume 是否恢复必要状态，避免重做已完成工作？
- 是否保留足够用户输入和状态，提示具体恢复动作？
- 是否吞异常、catch 过宽、错误翻译不当或丢上下文？
- 补偿、清理及恢复本身失败是否跨入口一致？

追踪 IO、commit/rollback、retry/resume/restart/status。隔离注入步骤间失败再重试/重启，对照持久状态与副作用。一起查预览/提交/恢复和批量/单条。使用支持的故障注入或夹具，不在生产制造破坏性故障。
