# Python 检查

从 `pyproject.toml`、锁文件和现有工具推导命令。除非用户要求迁移，否则不得引入并行的格式化器或依赖管理器。

没有现有约定时的推荐基线：

1. 语法/字节码编译：`python -m compileall -q <source-directories>`。
2. Ruff lint：`ruff check .`
3. Ruff 格式检查：`ruff format --check .`
4. 项目采用类型标注时进行静态类型检查：`mypy .` 或已经选定的类型检查器。
5. 单元测试：`pytest`；只有组件边界确有必要时才增加集成测试。
6. 对发布的入口执行导入或 CLI smoke test，特别是在单元测试不会导入全部生产模块时。
7. 对可分发包运行 `python -m build`、`twine check dist/*`，并在干净环境中安装构建出的 wheel 后执行 smoke test。

将 `python -m compileall` 视为有限的语法/字节码检查，不能替代导入、lint 或测试：很多缺失依赖、错误名称和运行时路径只有在导入或执行时才会暴露。针对项目声明支持的 Python 版本运行测试，避免任意扩大矩阵。使用仓库中已锁定且可复现的安装命令。按照项目类型和工具策略提交锁文件，并明确审查依赖变更。

不能因为仓库含有 Python 就强行构建制品。应用只有在确实部署 wheel、容器、可执行文件或平台包时才构建相应制品；脚本和内部工具可能只需检查与测试。测试对象应与最终发布或部署的制品一致。

工具支持时，将配置集中在 `pyproject.toml`。确保包元数据、Ruff、类型检查和 CI 的目标 Python 版本一致。对库项目，只有项目承诺支持最低依赖边界时才测试这些边界。
