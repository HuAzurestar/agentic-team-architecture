# 弱审：API

扫描内部及公开契约和消费者；每点可发现多个独立问题。

- 名称能否不读实现就表达行为、输入输出及副作用？
- boolean、optional/null/default 和参数组合是否明确？
- 是否混合不同动作或不必要地暴露存储结构？
- 方法、返回结构、错误、分页、筛选及排序是否符合项目惯例？
- 是否要求用户手填本可自动解析或选择的内部 ID？
- 是否重复接口或为单个调用方引入过度特殊能力？
- 既有语义、默认值、异常、顺序或空值兼容是否改变？
- 直接/间接调用方、序列化及空/错误结果是否适配？
- 是否有其他入口绕过校验、权限、事务或筛选？

追踪路由/schema→service→serializer→client/tests；搜 export/download/serialize 及同义业务路由。尝试畸形、缺失、矛盾、陈旧输入和旧调用形态。批量/单条入口一起检查；依据契约后果报告，不能只表达命名偏好。
