# 弱审：data

先从需求推导不变量，再看作者声明字段。

- 金额、数量、归属和派生统计是否守恒或满足承诺？
- 重复关系、循环、缺前置和矛盾状态是否漏计/重复计？
- 是否验证真实条件，而非信任 qualified/closed/same_source 等声明？
- 事务是否覆盖完整业务，网络和部分提交是否恰当处理？
- read-modify-write、check-then-act 是否竞争、丢更新、重复创建/扣款？
- 锁是否覆盖实际进程/部署边界，顺序及事务行为是否正确？
- 请求、队列重投、重试、重启和恢复是否按承诺幂等？
- 陈旧版本、乱序消息及冲突写者是否有确定结果？
- 预览、校验、提交、导入和历史重新启用是否应用同一规则？

搜索计算、状态修改、commit/rollback/save/flush 和唯一约束。尝试 empty/null/zero/negative/extreme、乱序/重复关系、循环、缺条件及部分完成。写操作尝试顺序重复、并发重复、旧版本写入及步骤间重启。仅操作授权隔离数据，记录预期不变量、实际结果和同根因入口。
