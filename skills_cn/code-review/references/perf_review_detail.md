# 弱审：perf

优先高频、大数据和关键路径，先给实际规模假设。

- 嵌套循环、重复遍历或中间层是否明显恶化复杂度？
- 循环 IO/DB/network 是否 N+1 或重复访问？
- 数据集/文件是否不必要地全量入内存，需 streaming/pagination/batch？
- list/cache/queue/retry/工作提交是否无界？
- file/connection/thread/process/临时资源在成功与失败后是否释放？
- 昂贵计算/序列化是否重复，是否有已证明的批处理/复用机会？
- cache 是否符合权限、失效和内存限制，而非臆测优化？
- abstraction 是否在实际热点倍增调用？

追踪关键循环、查询、资源获取/释放和调用频次，比较实际适用规模如 100/10,000 下的工作与 IO 数，必要时包含重复/循环输入。区分测量和复杂度估计，不要求所有规模 benchmark 或无关路径缓存。
