# 弱审：core

逐点扫描真实差量和同类实现，保存证据或 UNKNOWN/N/A 理由；输出问题，不按问卷计分。

- 能否用 1～3 句说明核心功能，主要改动能否映射已确定需求？
- 是否缺功能、加入未要求能力或未经决定改变产品语义？
- 每项能力是否标明复用、适配或新增，并有已有代码依据？
- 新表、状态、框架及抽象是否解决当前问题，已有机制为何不能承担？
- 模块职责和层次是否合理，规则是否散落到无关模块？
- 是否有循环依赖、错误依赖方向或过度了解其他模块内部细节？
- 是否重复已有 helper/service 的计算、校验、映射或序列化？
- 区分文本重复、语义重复、有意重复及需要一致的公共机制。
- 是否有未调用新增符号、未删除旧路径、不可达分支、废弃 flag 和注释历史实现？
- 权限、日志、重试、上下文、校验、事务、异常转换是否有已经证明值得统一的横切逻辑？

映射需求→模块，扩散定义/调用方/同类 helper。搜索语义等价表达，例如 available amount 也可能是 total-consumed。尝试 happy path 遗漏场景。判断死代码前检查注册、反射、插件、配置和入口；不能仅因两处相似就要求抽象，须说明实际后果。
