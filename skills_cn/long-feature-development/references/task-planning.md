# 任务规划与拆分

在已有 Feature 中新增、拆分或连接工作时读取。流程和分派由调用方决定；本文件定义可使用的规划产物，不指定必须由哪个角色规划。

## 输入与产出

使用业务目标、约束、优先级、适用的 INT/REQ/SOL 版本与外部授权，产出包含范围、预期结果、完成条件、依赖和返回位置的任务详情。被委托的规划者分配不冲突的稳定 ID，不为继续工作而要求用户发明内部编号。

将无法安全推导的产品选择、权限或实质范围歧义交回外部编排者处理，不把内部记账交给用户；何时主动澄清、交流渠道与提问方法属于其作业方式。计划用业务语言表达，追溯 ID 可作补充。内部任务 ID 可由规划者分配，但 feature-key 只能由外部提供，不能一起生成。

## 依赖与范围

- 当范围、负责人、候选版本、完成条件或权限需要独立跟踪时拆分任务，不规定固定的设计/开发/评审/测试/发布链。
- depends on 使用已存在的任务 ID，且不能成环。按需关联设计点或版本化 inputs；任务 ID 不需要等于设计点 ID。
- 依赖 DONE 只代表工作已完成并记录，不代表结果通过。若后续工作要求成功结果或批准，应写进消费方完成条件或外部定义的 GATE。
- 范围变化时检查受影响依赖、评审/测试目标和剩余工作；暂缓或被替代的工作要有处置说明，不能从计划中静默消失。

## 通过外部状态接口创建

读取现有 ID 与来源版本，准备任务详情，再按[生成区规范](generated-indexes.md)通过脚本更新 TASKS 表格和依赖拓扑。没有实际开始作业时，新任务保持 PENDING。状态维护者负责并发写入协调，本 skill 不使 ID 分配或写入自动具备原子性。

按照 [SKILL.md](../SKILL.md) 的固定维护步骤，每次操作必须完成索引同步与记录校验。校验器检查 ID 重复、依赖缺失/环、本地引用版本和预览漂移，不分配 ID、不写业务记录。失败或部分写入应报告修复，不能声称创建成功。生命周期变更参见 [transitions.md](transitions.md)。
