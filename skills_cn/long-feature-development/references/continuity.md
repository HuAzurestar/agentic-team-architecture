# Feature 续接与反馈

解析 Feature key 与外部管理根目录。STATUS 是 repository、feature、dev 等综合状态的统一管理入口，提供仓库关联与同步/集成概况、Feature/开发进展、当前焦点、状态/授权入口、阻塞和下一步，不只服务于续接。DESIGN、TASKS、VERBAL 分别保留自己的索引和内容；STATUS 仅概括状态并链接必要详情，不复制这些模块。续接时读取当前所需的 YAML 详情和版本化输入。

Project 是一个 Repository 的本地/remote 同步和基本规则记录，一个 Feature 可跨多个 Project。通过外部配置解析本机位置，不要求管理目录是 Git 仓库。

## 开始或恢复

1. 使用外部明确提供的 Feature key、目录映射、委托及状态/授权接口，不自行分配 key。标识缺失时交回外部编排者取得，不用临时目录猜测归属。先用 STATUS 理解整体上下文，再读选定设计/任务详情及必要版本化输入，不预载全部仓库文档或临时附件。
2. 核对输入决定、候选身份、完成条件、当前负责人及原 resume action。缺失/冲突时报告，不编造批准，也不静默迁移旧记录布局。
3. 代码工作读取 [repository-context.md](repository-context.md)，比较相关实际 refs、脏变更与记录点。存在中断或部分写入时，在受影响修改前应用 [checkpoints.md](checkpoints.md)。
4. 按 [SKILL.md](../SKILL.md) 在操作前运行只读记录校验，内容/状态操作后同步索引并再次校验；首次初始化按入口中的例外先由 agent 准备记录。校验不证明业务就绪、Git 对象或权限；失败不能被描述为恢复成功，报告范围并保留可用只读上下文。

保留可用的局部上下文，同时报告缺失或冲突事实。状态维护者负责持久化、同步与写入协调；校验器只读，索引更新通过[生成器](generated-indexes.md)完成，仅修改生成区，不写详情状态。

## 反馈与纠正

反馈保存为 FEEDBACK 任务或其他任务中的反馈段落，保留观察、受影响版本、请求、处理决定和解决结果。后续可能是澄清、INT/REQ/SOL 修订或开发返工；具体路由由外部决定。

保留原决定/报告，并通过持久记录关联纠正，判断哪些下游证据和决定可能过期。不静默替换历史批准，也不把旧证据当作对新版本的验证。

VERBAL/gists 不属于恢复上下文或依据；任务 gists 专用字段仅是可选参考登记。删除全部临时附件与附件索引后，Feature 仍需可理解、可校验；用于判断的分析结论和报告应事先保存到 design/tasks。

## 结束或交接

在持久记录中保留实际任务状态、候选/产出点、成功恢复点及未保存范围、检查与限制、待决定项、下一步和后续负责人。按 [checkpoints.md](checkpoints.md) 使用获授权的持久化方式；交接请求和回执按 [handoffs.md](handoffs.md)。

由维护者核对已修改详情/预览，只更新受影响的 STATUS 整体上下文。说明实际核实了什么、还有什么不可用；未校验、未保存或未解决的结果不能声称已完成。
