# 标准能力 I/O 索引

设计稿 draft-1。Skill 定义明确输入如何加工为可验证输出；Agent instruction 按用户理念组织职责、派发和决定权；runtime 绑定提供物理访问。具有能力不等于获得权限。

通用输入：请求/来源身份、Feature/任务关联、准确输入及版本、范围/约束、适用授权、runtime profile 和返回约定。通用输出：实际操作、版本化产物、检查/限制、结果、未决项及正式记录状态。区分事实、推断、建议和实际决定。

| 能力 | 输入 → 输出 | Reference |
| --- | --- | --- |
| PM 接入 | 明确 runtime 初次配置 → 已验证配置或具体缺项 | [runtime 持久化](runtime-persistence.md) |
| 意图关联与分流 | 原始来源和已知 Feature 上下文 → INT、去重/关联结论、澄清点和工作入口 | [设计](decisions.md) |
| REQ/SOL 分析 | INT/现状/约束 → 版本化需求与方案提案、选项 | [设计](decisions.md) |
| 人工/代理决定 | 准确提案及有效委托/实际答复 → 可归属的范围内决定与影响 | [确认](confirmation.md) |
| 规划与派发 | 已批准范围及就绪条件 → 任务、依赖和明确交接 | [规划](task-planning.md)、[交接](handoffs.md) |
| 执行 | 明确任务/候选/范围/授权 → 实际产物和必要验证 | [任务闭环](task-workflow.md) |
| REVIEW/TEST/返工 | 准确目标/条件/发现 → 报告、修订候选及适用复验 | [质量](task-contracts.md) |
| 验收/GATE | 候选/条件/策略/证据 → 分别记录实际答复、条件与授权 | [验收](acceptance.md)、[关口](gates.md) |
| 通知 | 实际流程事件 → 持久事件/真实回执或关联回复 | [hook](notification-hooks.md) |
| 上线交付 | 明确动作/受众/候选/授权 → 合并/部署、文档、公告或对外交接结果 | [交接](handoffs.md) |
| 恢复 | 实际记录/版本及未完 attempt → 核对后的下一步 | [续接](continuity.md) |

设计、执行、上线是便于组织的三类工作，不强制每次走固定阶段。上线可含更新文档、告知外部人员和公告，只按实际范围实例化。角色缺项列为明确决策点；公司提供谁能批准、START 轮次及最终完成权限。
