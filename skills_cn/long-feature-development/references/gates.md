# GATE 任务

GATE 是任务类型。由调用方提供对象、策略、条件、证据要求、决定权限和后续动作。本 skill 不定义公司阶段、发布顺序或谁必须操作。

使用通用任务 YAML 与正文。gate 字段保存 subject、policy ref、criteria、evaluation、authorization、decision ref、allowed actions；持久证据写入 result.evidence 和任务报告，引用标识实际版本。

尚未配置的模板可保留 evaluation=unknown、对象/策略为空且不允许动作。声明 satisfied 或 unsatisfied 前，确定对象、策略与条件。缺失或无法检查的条件保留未决，不当作通过。

evaluation 与 authorization 分开。检查满足可以继续等待批准；granted 引用相应 DECISION 任务或外部版本化决定。not_required 必须由外部策略支持，不能绕过未知授权边界。正向检查不直接执行动作。

## 需要用户决定时的交流协议

GATE 是通用层唯一可以把用户交流设为阻断前置条件的记录类型；是否需要用户决定仍由该 GATE 的外部策略明确，不把所有 GATE 都变成人工审批，也不取消已有代理授权。

策略要求用户决定时，维护者必须准备并提交明确请求：对象和版本、需要决定的问题、条件与证据、剩余风险、拟允许的后果，以及指定决定者。请求及其来源/时间保存在本任务或关联持久记录中；具体渠道、工具、措辞和主动跟进方式由外部 orchestrator/宿主提供，本 skill 不绑定某个 UI 或消息工具。

没有实际答复时 authorization 保持 pending，记录等待对象、后续负责人和继续条件，不允许依赖该授权的动作。脚本同步成功、技术检查通过、沉默或 agent 推断均不能代替用户答复。

收到答复后，保留实际确认者、答复原文/来源、时间、对象版本和允许范围，用 DECISION 或外部版本化决定引用承接授权。自然语言可以有效，但含糊、过期或针对其他候选的答复不能冒充当前授权；对象变化时按策略重新评估或重新请求。普通需求澄清、进展交流和非阻断验收材料不因此被通用 skill 固定成沟通流程。

## 核对实际候选与前置结果

作出结论前，确定当前对象和外部策略要求的前置项，检查相关依赖结果、开发产出、已测/已审/已验收候选点，以及适用的汇入或 PR 两端。任务 DONE 不证明结果通过，也不证明其证据覆盖当前对象。

比较实际版本，而非只数任务 ID 或完成数量。证据面向其他候选时，按策略判断并记录适用性，不能静默声称当前候选已被检查。缺失检查、无法解释的版本不匹配和未处理的必要发现保持未决；暂缓工作需要明确处置，不能消失。

## 保存结论，不代为执行

在任务中记录对象/策略版本、证据、条件判定、未决项、实际决定和允许后果。策略允许 Feature 流转时，由指定维护者更新受影响 STATUS 概况和下一步，不复制任务报告。

判定失败可以完成“检查 GATE”的委托，但不能写成 GATE 满足或 Feature 已成功流转。任务 DONE 或 agent 总结不证明已经可以发布。记录 allowed action 也不证明动作已执行；获授权执行及其回执分别跟踪。

工具只检查结构一致性：satisfied 有持久证据；允许动作还需 satisfied 且 granted/not_required。它不判断条件、不验证权限、不联系决定者。必要结果与依据保存在任务/设计记录，不依赖临时附件。

### 流程通知I/O

可通过[通知hook](notification-hooks.md)表达实际条件判定或授权请求，带准确对象/版本及决定者。接收器订阅或工具受理不改变待定授权及允许动作。
