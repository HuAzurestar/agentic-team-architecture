# Existing tools and unsupported capabilities

F02 selects prompts and source text. It does not provide an environment write engine, a configuration orchestrator or a provider service. The existing `task_state.py`, `task_create.py` and `task_checkpoint.py` own task/Git writes; none is a general background conditional-write API. Their atomic-file behavior does not prove platform-wide compare-and-swap or two-process background-write correctness.

Use existing editor/Git or an available provider only for the explicit authorized operation and verified target. Manual edit/backup is a separate action; `context.py` never offers init/apply/backup or silently switches to another customer source. With ordinary filesystem tools, exclusive creation (for example mode `xb`) can create a byte backup without overwriting. A successful copy alone does not prove conditional replacement, Windows DACL/stream preservation, or unknown-response recovery.

Classify unavailable service, missing driver, ambiguous binding, read-only binding and denied update separately from service health. Check only the selected binding through a verified read-only capability interface. Without that interface, retain `UNKNOWN`/unsupported and the local DIRECT route; do not infer access or test a write. Never emit raw configuration, credentials, another binding or a provider's raw exception. This Skill has no provider port, so it does not claim those service checks were executed.

Before any background/configuration write, the chosen existing tool must verify the exact source identity and full original-content/native condition. A stale condition stops the write even when mtime matches. Missing conditional-write, metadata-preservation or process-lock support means refuse automated apply and describe the manual route; never replace it with an unconditional write. Keep raw new/old data and recovery references when the outcome is unknown.

When a configuration update succeeded but background bookkeeping failed, query the exact original instance/ID first. Do not repeat create/update/unbind on an unknown result, choose another binding, or remove the only backup. Unbinding modifies only the authorized routing relationship, never user source data. The real F07/F08 services and F15 combined delivery own atomic writes, concurrency and service-side recovery tests. Their absence is not a failing DIRECT read and is not evidence that those tests passed.

Coverage ownership: AC01–06 and the local isolation/inert-text portion of AC16 are F02 context behavior. AC07 is capability refusal and explicit classification guidance; service probing requires the external interface. AC08 uses existing exclusive filesystem creation. AC09–12 require the selected conditional writer; AC13–15 require the real configuration/recovery interface. Preserve these distinctions in test and acceptance records.
