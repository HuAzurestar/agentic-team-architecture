# 检查点与中断恢复

长耗时/高风险操作前、交接前，或恢复未完成实现/状态写入时读取。宿主提供有权使用的检查点方式；本 skill 不要求管理目录使用 Git，也不静默授权 commit。

## 记录恢复点

连贯工作单元完成后、长耗时/风险操作前和交接前，使用可用且已授权的持久化方式。保留任务身份、输入版本、已观察产出点、检查及限制、未保存/残留工作、准确的 resume action 和已知阻塞。正式检查点说明保存在任务中，临时日志不能是唯一上下文。

代码检查点可以是获授权的有范围本地 commit，也可以是宿主提供的等效快照。说明实际保存了哪些材料以及保存位置，不能只写了一段总结就声称已经持久化。

## 安全检查残留

恢复后，在进一步写入前检查相关实现仓库 staged、unstaged、untracked 变化及 Feature 状态的部分写入，判断哪些路径和变更属于中断任务。脏工作树是需要核对的事实，不代表可以删除、reset、stage 或 commit，也不自动阻止无关只读工作。

保留用户变更和无关预暂存内容；保存自己的残留前先审查，适用时测试。仅在范围隔离且已理解时继续；归属、候选身份或重叠改动仍不明确时，停止受影响的修改，通过外部接口取得方向。

选择 Git 检查点时显式列出自己的文件，检查暂存内容有无无关改动/秘密，将本地检查点与 push/merge 分开；遵守项目授权，不假设旧脚本或自动 commit 策略仍存在。

## 核对与交接

通过 [repository-context.md](repository-context.md) 对照仓库实际点与记录点，由指定维护者核对任务详情、预览和受影响 STATUS。部分写入不是完整检查点，结构校验器也不验证 Git 祖先关系或快照持久性。

在持久记录中保留最近成功恢复点、未保存范围、测试/结果、准确下一步、阻塞及后续负责人。缺少持久化时如实说明。恢复边界是最近一次成功保存；任意断电瞬间零丢失需要宿主/编辑器/文件系统支持，本 skill 不作此保证。
