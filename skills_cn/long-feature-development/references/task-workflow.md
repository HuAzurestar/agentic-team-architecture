# 作业一个任务

执行任务时读取，尤其是未给定特定编排的情况。这是默认的局部任务闭环，不是公司交付流水线，也不分配公司角色。

## 选择作业流程

先读取调用方给出的编排要求；指令或其引用位置应明确任务选择/分派、必要检查、交接/返回及适用审批边界。已给定部分按其执行；局部任务闭环未指定时使用下述默认法，不能替换或静默绕过已配置前置条件。要求不清或冲突时保留受影响动作的未决状态。两种路径都遵守公共状态/记录含义、每次操作维护及现有授权；不会产生新权限，也不自行选择状态维护者。

## 默认闭环

1. **明确范围与就绪条件。** 执行[开始/恢复](continuity.md#开始或恢复)及操作前校验。在获准请求内使用已分派任务或记录中的当前焦点；需要拆分时走[任务规划](task-planning.md)，不要求用户提供内部 ID。读取任务详情、完成条件、版本化输入及适用设计决定。开始 PENDING 任务前，要求依赖 DONE，并检查所需成功结果/批准。等待依赖仍是 PENDING，不跳到无关任务，也不因依赖 DONE 就推断获得权限。涉及代码时按[仓库上下文](repository-context.md)核对实际检出、refs 与残留。
2. **记录开始。** 通过指定写入接口记录实际 owner、started at、范围/输入版本及相关 Project 限定的基线点，再 PENDING → WIP。已有 WIP 从保留的作业轮次续接；DONE 按[状态转换](transitions.md)显式重开，不覆盖完成历史。更新后生成索引并校验。
3. **作业与验证。** 只执行委托范围，涉及测试/评审/返工时读取相应[任务契约](task-contracts.md)。关键推理、实际检查/结果和候选版本保存在持久 design/tasks 中。长耗时/风险工作及交接前按[检查点](checkpoints.md)保存连贯恢复点，不推断已有 commit/push 权限。每次记录变更均执行维护步骤。
4. **记录结果。** 委托作业就绪时 WIP → RECORDING，在任务中保留实际结果、已执行检查、证据、限制和剩余工作。按[结果/证据格式](protocol.md#tasks-元数据与预览)填写：evidence 条目是版本化引用，实质验证报告保留在任务正文中。只有委托/策略需要时才使用[验收](acceptance.md)或 [GATE](gates.md)。测试通过不代表获得批准；已完成的测试或决定处理任务也可能记录失败或拒绝。
5. **收尾并返回。** 核实完成条件和持久化结果。代码产出按各受影响 Project 记录实际已保存的 project@SHA；没有时保持记录未完成，不编造 SHA。非代码工作不需要提交点。满足条件后记录 completed at 与 DONE，再更新受影响 STATUS 概况、生成索引并校验。只有最终状态已持久化且校验通过后，才报告完成；写入/校验失败是维护未完成，不算成功收尾。通过指定接口返回结果、产出点、检查/限制和下一步；请求/回执按[交接](handoffs.md)处理。不自动合并、发布、部署或开始委托范围外的下一任务。

## 中断与返回路径

- 已分派任务遇到具体障碍时 WIP → BLOCKED，记录阻塞、影响、解除条件、后续负责人和 resume action；确认解除后恢复 WIP。
- 没有具体障碍的中断保留 WIP 和精确续接动作；分派前等待前置任务仍为 PENDING。
- RECORDING 中发现候选工作未完成时，记录失败检查和下一步，返回 WIP。持久化/校验失败时，核对修复前停止依赖其结果的完成/交接声明。
- DONE → WIP 记录重开理由，保留先前结果，并按适用权限开始新轮次。不把旧检查当成对新候选的证据。

转换含义和必要记录以[状态机](transitions.md)为准。每条路径的每次记录修改均遵守[维护契约](../SKILL.md#每次操作的固定维护步骤)。默认闭环不强制新增独立评审、测试、验收或 GATE 任务；实际范围/策略要求时才设立。
