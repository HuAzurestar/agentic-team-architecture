# 仓库身份、实际提交点与集成上下文

定位 Project 本地检出、对比记录与实际代码状态，或准备集成/评审/PR 交接时读取。仓库拓扑与 Git/forge 策略来自项目，本文件定义需保留的事实。

## 操作前确认身份

通过稳定 project.yaml 和调用方的设备/操作系统映射解析 project key。历史本地路径只是线索，不是仓库身份证明；使用可用只读证据确认目标检出与 remote 身份。不在含糊或不匹配的检出上操作，不自动 clone/搬迁或静默改写 Project 配置。

Project 定位器只返回配置位置，不证明检出存在、remote 最新、commit 存在或缩写 SHA 唯一。

## 区分引用含义

适用时作为任务专用元数据分别记录下列事实；STATUS 保存仓库整体状态，不复制详细注册表：

| 事实 | 含义 |
| --- | --- |
| 作业区域与已观察 HEAD | 本次 attempt 实际使用的 Project 限定分支区域及字面提交点。 |
| 汇入对手 | merge/rebase 输入的准确分支/提交点，不用移动别名替代之前的输入。 |
| PR/MR source 与 target | 评审/合并两端及其已观察点，可能不同于本地作业 HEAD 或汇入对手。 |

跨 Project 任务分别标识各仓库点；分支同名不意味着仓库相同。冻结点用 project@SHA，区域用 project@branch，参见 [protocol.md](protocol.md#点与区域)。不能把一个“当前 SHA”当作上述全部事实。

## 对照事实，不重写历史

检查相关本地 refs、脏变更，以及可获得且有权读取的 remote 观察。修改代码或声称旧测试/评审/验收仍适用前，先比较记录点与实际点。若流程依赖祖先关系或依赖代码已汇入，应在真实 Repository 中核实；结构校验器不执行这些检查。

分支或 PR 移动时保留之前评审/测试的点，另记新观察；判断哪些作业或批准需要补做，不重写旧报告目标。无法取得的 remote/CI/forge 状态标为未核实，不猜测最新。

解析引用不自动授权 merge、push、部署或其他远端修改。遵守外部项目策略；本 skill 不固定集成分支数量或 PR 数量。
