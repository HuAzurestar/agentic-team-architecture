# Project environment

## Common

Background is optional reference material, never authorization or live task state. Keep credentials in the host's existing secure configuration. Confirm each document's editing authority from the project entry.

## Example environment

### Route

Supply the project-management directory explicitly. Record stable repository aliases, location hints and expected remote identities here. Keep worktrees, branches, task IDs and current SHAs in STATUS.md and task records.

### Evidence

Record the source and date of environment observations. Recheck repository identity and any selected provider capabilities when used; a healthy service is not write permission.

### requirement

Locate the current business scope and observable acceptance cases from the project entry.

### solution

Locate architecture constraints and supported interfaces relevant to the selected requirement.

### development

Use the selected repository's implementation and test instructions.

### review

Locate the full checklist and original sources for the frozen review candidate.

### delivery

Locate the project's authorized integration, backup and delivery route. Keep user records outside the installed Skill directory.
