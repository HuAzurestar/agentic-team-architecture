# Quality evidence and release boundaries

Task completion is not quality success. A completed review may contain blockers, and a recorded human REJECTED/REWORK acceptance may complete its task without allowing integration. The complete quality policy must check current review/test details, full requirement/solution coverage, independent blocker closure and applicable human evidence in distinct pre_accept, pre_merge and post_merge phases. Legacy incomplete records must not be silently promoted. That aggregate policy and its task/host wiring are not implemented by the reader below.

## Actual Git integration correspondence

`quality_git.observe_integration(IntegrationBinding(...), phase, result_sha=...)` reads actual local Git objects and refs. The host independently supplies registered repository identity, source branch/SHA/tree, target branch and frozen target-before SHA. Branch names are validated; the repository root and configured remote identity must match. The reader checks both branches and repository identity before and after observation. It disables replacement objects through the shared Git runner and refuses local graft files. It does not fetch, update refs, refresh the index, merge or push.

Before acceptance/merge, the source ref must still equal the frozen source and the local target must equal target-before. Target-before must be an actual ancestor of source, and the source's actual complete tree must equal the retained candidate tree. These facts establish the expected tree for a normal merge of that already-synchronized source; they do not authorize one.

After merge, target must equal the exact result SHA, source must remain the frozen candidate, result must contain source as an ancestor, and result's complete tree must equal the retained candidate tree. A normal no-fast-forward merge can therefore have a different SHA without automatically invalidating the accepted content. A fast-forward can satisfy the same correspondence. A moved target, unsynchronized source, changed result tree or squash/rebase without the required ancestry fails closed. Equivalent-looking diffs alone do not transfer approval.

The result is only `valid` local correspondence with explicit source/tree/target-before/result facts. It always has `quality_assessed=false`, `merge_authorized=false`, `remote_target_verified=false`, `worktree_verified=false`. The consumer must independently verify the authoritative remote target, clean application workspace, current tests, review closure, scope, human decision and actual operation grants. It must not label this read-only result a quality pass. Git subprocesses use the shared 50-second per-command I/O budget; this is separate from the future pure policy's 2 CPU-second aggregate budget. A final observation does not lock refs against later movement; revalidate at the operation boundary.
