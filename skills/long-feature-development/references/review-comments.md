# Editable review comments

`review_comments.py` provides a bounded in-memory Markdown codec, selection and conversion preview. It does not read remote authority, publish comments, change point decisions, update tasks, assess quality, or prove verification merely because a record says VERIFIED. Those workflow integrations remain required.

New records have `rv_id=RV-<UUID>`, `Target={feature,ref,selector?}`, `Basis={source_key,source_text,git_basis?,line_start?,line_end?}`, `Status`, `Comment`, and optional `Resolution`/`Verification`. Status is PENDING, ADDRESSED or VERIFIED. A record's identity is `(feature,reviews_ref,rv_id)`; the review document reference is supplied independently from its commented target. New UUIDs are allocated once by `new_review`; an uncertain publication must search that same UUID before creating another.

## Safe Markdown format

The document begins with `# Reviews`. Each `## RV-<UUID>` block contains `- Status: PENDING` and dotted Target/Basis scalar fields. Every scalar is a JSON string, including decimal line numbers, for example `- Target.feature: "PIRC-31"` and `- Basis.line_start: "1"`. Git basis, when present, is a full actual SHA, not the REVIEWS document version. Source text is not stored in a scalar: it appears under `### Source`. Comment, Resolution and Verification use equally named level-three headings. Every text line, including empty lines and apparent Markdown headings, is prefixed with `> `. Newline semantics are LF; CRLF document input is accepted and its original is retained. Unknown/unquoted content, duplicate fields/IDs, invalid versions or cross-feature content fail closed, rather than being silently discarded.

`parse(text, feature=..., reviews_ref=...)` returns records, linear identity/target indexes, original source and its digest. `select(parsed)` defaults to PENDING; explicit status filters read the requested states. Explicit RV IDs without a status filter read any state, and unknown requested IDs are errors.

## Legacy and conversion

Known old `OPEN/open`, lowercase statuses and `closed` are mapped only in memory. A `- Basis: <free text>` field is retained in legacy metadata; its provenance is unresolved, never guessed. Parsed legacy records carry `_legacy` and cannot be directly rendered. Preserve the original source. Explicitly resolve the Basis, remove the legacy marker in the proposed copy, and call `preview_conversion(original, proposed, ...)` before editing. The preview retains the original digest, requires unchanged identities, supplies the complete proposed document and a bounded before/after changed span, and always returns NOT_APPLIED. A truncated diff is not full review; display the complete affected material before any later authorized conditional write. Removing the marker is not authorization or proof that a user saw the preview.

Each operation accepts at most 1,000 comments/4 MiB; parsing/rendering has a 2 CPU-second limit. The codec performs no I/O or logging. It deliberately does not implement platform authority, conditional writes, draft recovery, stale-basis checks, or agent consumption acknowledgments yet.

## Foreground authoritative Git reads

Before review work, or an explicit request to read review content, invoke `review_source.read_for_purpose` with the independently registered Git binding (`repo`, remote name, exact expected remote URL, repository reference, review path, feature and review reference). The foreground entry defaults to PENDING but honors explicit status/ID requests. An absent binding is UNBOUND_EMPTY; a declared binding that cannot be read is an error, never an empty success. A reachable remote tree proving the file absent is a genuine empty state. Other purposes do not trigger reads unless explicitly requested. There is no background polling or interruption service.

`read_git_reviews` verifies repository/remote identity, observes actual remote `refs/heads/master`, fetches that exact SHA into a private temporary bare repository, reads the bounded regular blob and observes remote master and working HEAD again. It never substitutes the working branch or a cached remote-tracking ref for remote master, never changes working refs/index/files/FETCH_HEAD and never merges or pushes. Reading may proceed while the working tree is dirty; applying comments may not. The source SHA and working HEAD are reported separately and do not replace the commented target's Basis. A moving source, invalid source, missing master or inaccessible remote stops the read.

The fetch uses shallow history and requests blob filtering. Git transport/pack cost is separate from the 4 MiB review-document limit; a server may not support filtering. Each Git subprocess has a 50-second timeout, terminal prompting is disabled, and diagnostics are not returned because they may contain credentials. Only file/http/https/ssh/git transports are enabled; host credentials/transports still need actual environment setup and validation. Local-remote fixtures prove Git behavior, not live forge authentication. Temporary fetched objects are removed on return; they are not merged into the working repository.

Results report whether the working history contains the observed master, but always `application_authorized=false` and `agent_consumed=false`. Before editing/releasing, the next workflow must verify authorization, clean state, incorporate the exact observed master when required, recheck samples and source movement, then conditionally publish. That application/publishing integration and native-provider transport remain pending.

## Application preflight

`review_application.assess_application` verifies actual expected branch/HEAD, strict host authorization and clean state, re-reads the authoritative document, checks the selected records against it, and reports the exact missing master SHA as `MASTER_SYNC_REQUIRED` without merging. Dirty-state checks use the checkout's installed Git text/filter configuration; disabling global autocrlf would falsely report some clean CRLF checkouts as dirty. The configured repository root is rechecked and optional index writes remain disabled.

After master is contained, independently supplied `GitSampleBinding` entries bind each Basis source key to a repository, relative file, expected current HEAD, target reference and feature. Current material is read from real Git/worktree facts, not from the comment. Point selectors or explicit line ranges are supported, not their ambiguous combination. The recorded full historical Git Basis must exist and contain the quoted original sample. Current differences return `BASIS_NEEDS_RECHECK` and a bounded diff without changing comment status. Unsupported selectors, missing historical versions or native sources remain unverified, not silently accepted. Unique current-material bodies are bounded to 4 MiB and re-read after the remote observation.

A passing result is only preflight at the observed versions. Its trace and sample-check output are returned in memory, not persisted. It remains `NOT_APPLIED`, does not grant merge/release permission, and does not prove independent review or acceptance. The F03 operation writer still needs integration to persist intent before exact-master synchronization, preserve conflicts/unknown effects, reconcile, revalidate samples and conditionally publish. No alternative unjournaled merge path is supplied here.

## Durable implementation-repository synchronization

`review_sync.prepare(feature, gist, repository, binding, observation, authority_source_ref, authority=True)` validates the full F03 context, independent registered repository binding, actual authoritative source and selected comment originals. It persists `operation-v1` / `review-master-sync` in a declared tracked gist before any merge. The record retains working branch/HEAD, exact master SHA, original review observation and metadata snapshots. Strict host authorization is required; a string in a document is not permission. An unresolved sync for that repository must be reconciled before preparing another.

`review_sync.execute(..., operation_id, authority=True)` revalidates the record, original metadata, clean working tree and remote observation, fetches the exact SHA without changing refs/FETCH_HEAD, and persists a dispatch marker before `git merge --no-ff` with the operation UUID trailer. A contained master needs no merge. The operation never pushes, aborts, resets, or resolves a conflict. A conflict leaves MERGE_HEAD, index and files intact. A lost response is reconciled against actual HEAD, ordered parents and UUID; a dispatched operation with no proven result is unknown and is never automatically replayed. F03 reconciliation repairs task/STATUS refs with original-or-desired checks and is idempotent. Read-only reconciliation does not write.

For a registered management repository, `review_sync_management` adds a journal-only local commit before merge. The retained working HEAD is the original H0; the intent commit J has parent H0 and changes only the declared gist, with exact expected content/mode and an Operation-Intent UUID. The merge must have ordered parents J and the observed master SHA. The same F03 coordinator is retained; only its exact untracked runtime lock is excluded from dirty-state checks, never user files or an uncommitted journal at merge time. Foreign staged changes are refused; the journal commit explicitly scopes its path. A remote change to the journal itself or collision with the coordinator path stops before dispatch. It is not silently resolved or overwritten.

Reconciliation preserves `DERIVED:HEAD` for the management repository and records the actual merge in task refs. Original-or-desired checks preserve new metadata brought in by the merge as a conflict requiring explicit resolution. A single subsequent metadata-only checkpoint can be inspected idempotently; unrelated changes cannot be hidden behind an old success receipt. A crash before/after the journal commit is inspected against actual Git content; an unknown merge is not automatically retried. No cleanup resets, forced checkout, stash, or implicit master push is performed.

Source freshness and target samples must be rechecked after synchronization, including when master advances during/after the merge. A recorded merge is not permission to apply comments, successful quality assessment or human acceptance. Conditional review publication, native providers and decision writers remain incomplete. Tests use actual temporary Git repositories, not live forge credentials or project-branch merges.
