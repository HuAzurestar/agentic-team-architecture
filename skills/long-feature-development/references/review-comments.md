# Editable review comments

`review_comments.py` is the bounded in-memory codec/selection/conversion layer, not a publisher or quality authority. The implemented [review workflow](review-workflow.md) joins remote reads, sample checks, synchronization and conditional publication. A VERIFIED label alone does not prove verification.

New records have `rv_id=RV-<UUID>`, `Target={feature,ref,selector?}`, `Basis={source_key,source_text,git_basis?,line_start?,line_end?}`, `Status`, `Comment`, and optional `Resolution`/`Verification`. Status is PENDING, ADDRESSED or VERIFIED. A record's identity is `(feature,reviews_ref,rv_id)`; the review document reference is supplied independently from its commented target. New UUIDs are allocated once by `new_review`; an uncertain publication must search that same UUID before creating another.

## Safe Markdown format

The document begins with `# Reviews`. Each `## RV-<UUID>` block contains `- Status: PENDING` and dotted Target/Basis scalar fields. Every scalar is a JSON string, including decimal line numbers, for example `- Target.feature: "PIRC-31"` and `- Basis.line_start: "1"`. Git basis, when present, is a full actual SHA, not the REVIEWS document version. Source text is not stored in a scalar: it appears under `### Source`. Comment, Resolution and Verification use equally named level-three headings. Every text line, including empty lines and apparent Markdown headings, is prefixed with `> `. Newline semantics are LF; CRLF document input is accepted and its original is retained. Unknown/unquoted content, duplicate fields/IDs, invalid versions or cross-feature content fail closed, rather than being silently discarded.

`parse(text, feature=..., reviews_ref=...)` returns records, linear identity/target indexes, original source and its digest. `select(parsed)` defaults to PENDING; explicit status filters read the requested states. Explicit RV IDs without a status filter read any state, and unknown requested IDs are errors.

## Legacy and conversion

Known old `OPEN/open`, lowercase statuses and `closed` are mapped only in memory. A `- Basis: <free text>` field is retained in legacy metadata; its provenance is unresolved, never guessed. Parsed legacy records carry `_legacy` and cannot be directly rendered. Preserve the original source. Explicitly resolve the Basis, remove the legacy marker in the proposed copy, and call `preview_conversion(original, proposed, ...)` before editing. The preview retains the original digest, requires unchanged identities, supplies the complete proposed document and a bounded before/after changed span, and always returns NOT_APPLIED. A truncated diff is not full review; display the complete affected material before any later authorized conditional write. Removing the marker is not authorization or proof that a user saw the preview.

Each operation accepts at most 1,000 comments/4 MiB; parsing/rendering has a 2 CPU-second limit. The codec performs no I/O or logging. Remote reads, conditional writes, retained drafts and stale-basis checks belong to the implemented workflow below, not this codec. Publication does not prove Agent consumption; there is no background acknowledgment service.

## Foreground authoritative Git reads

Before review work, or an explicit request to read review content, invoke `review_source.read_for_purpose` with the independently registered Git binding (`repo`, remote name, exact expected remote URL, repository reference, review path, feature and review reference). The foreground entry defaults to PENDING but honors explicit status/ID requests. An absent binding is UNBOUND_EMPTY; a declared binding that cannot be read is an error, never an empty success. A reachable remote tree proving the file absent is a genuine empty state. Other purposes do not trigger reads unless explicitly requested. There is no background polling or interruption service.

`read_git_reviews` verifies repository/remote identity, observes actual remote `refs/heads/master`, fetches that exact SHA into a private temporary bare repository, reads the bounded regular blob and observes remote master and working HEAD again. It never substitutes the working branch or a cached remote-tracking ref for remote master, never changes working refs/index/files/FETCH_HEAD and never merges or pushes. Reading may proceed while the working tree is dirty; applying comments may not. The source SHA and working HEAD are reported separately and do not replace the commented target's Basis. A moving source, invalid source, missing master or inaccessible remote stops the read.

The fetch uses shallow history and requests blob filtering. Git transport/pack cost is separate from the 4 MiB review-document limit; a server may not support filtering. Each Git subprocess has a 50-second timeout, terminal prompting is disabled, and diagnostics are not returned because they may contain credentials. Only file/http/https/ssh/git transports are enabled; host credentials/transports still need actual environment setup and validation. Local-remote fixtures prove Git behavior, not live forge authentication. Temporary fetched objects are removed on return; they are not merged into the working repository.

Results report whether working history contains the observed master, always with `application_authorized=false` and `agent_consumed=false`. The implemented review_workflow checks current permission/clean state, journals exact-master sync when needed, rechecks samples/source movement, and conditionally publishes through the Git/native paths below. A read alone performs none of those writes.

## Application preflight

`review_application.assess_application` verifies actual expected branch/HEAD, strict host authorization and clean state, re-reads the authoritative document, checks the selected records against it, and reports the exact missing master SHA as `MASTER_SYNC_REQUIRED` without merging. Dirty-state checks use the checkout's installed Git text/filter configuration; disabling global autocrlf would falsely report some clean CRLF checkouts as dirty. The configured repository root is rechecked and optional index writes remain disabled.

After master is contained, independently supplied `GitSampleBinding` entries bind each Basis source key to a repository, relative file, expected current HEAD, target reference and feature. Current material is read from real Git/worktree facts, not from the comment. Point selectors or explicit line ranges are supported, not their ambiguous combination. The recorded full historical Git Basis must exist and contain the quoted original sample. Current differences return `BASIS_NEEDS_RECHECK` and a bounded diff without changing comment status. Unsupported selectors, missing historical versions or native sources remain unverified, not silently accepted. Unique current-material bodies are bounded to 4 MiB and re-read after the remote observation.

A passing result is only preflight at observed versions: `NOT_APPLIED`, without merge/release permission or independent-review proof. The composed review_workflow uses the F03 writers below for intent, exact-master synchronization, conflict/unknown recovery, sample revalidation and conditional publication. Do not substitute an unjournaled merge.

## Durable Git synchronization

`review_sync.prepare(feature, gist, repository, binding, observation, authority_source_ref, authority=True)` validates the full F03 context, independent registered repository binding, actual authoritative source and selected comment originals. It persists `operation-v1` / `review-master-sync` in a declared tracked gist before any merge. The record retains working branch/HEAD, exact master SHA, original review observation and metadata snapshots. Strict host authorization is required; a string in a document is not permission. An unresolved sync for that repository must be reconciled before preparing another.

`review_sync.execute(..., operation_id, authority=True)` revalidates the record, original metadata, clean working tree and remote observation, fetches the exact SHA without changing refs/FETCH_HEAD, and persists a dispatch marker before `git merge --no-ff` with the operation UUID trailer. A contained master needs no merge. The operation never pushes, aborts, resets, or resolves a conflict. A conflict leaves MERGE_HEAD, index and files intact. A lost response is reconciled against actual HEAD, ordered parents and UUID; a dispatched operation with no proven result is unknown and is never automatically replayed. F03 reconciliation repairs task/STATUS refs with original-or-desired checks and is idempotent. Read-only reconciliation does not write.

For a registered management repository, `review_sync_management` adds a journal-only local commit before merge. The retained working HEAD is the original H0; the intent commit J has parent H0 and changes only the declared gist, with exact expected content/mode and an Operation-Intent UUID. The merge must have ordered parents J and the observed master SHA. The same F03 coordinator is retained; only its exact untracked runtime lock is excluded from dirty-state checks, never user files or an uncommitted journal at merge time. Foreign staged changes are refused; the journal commit explicitly scopes its path. A remote change to the journal itself or collision with the coordinator path stops before dispatch. It is not silently resolved or overwritten.

Reconciliation preserves `DERIVED:HEAD` for the management repository and records the actual merge in task refs. Original-or-desired checks preserve new metadata brought in by the merge as a conflict requiring explicit resolution. A single subsequent metadata-only checkpoint can be inspected idempotently; unrelated changes cannot be hidden behind an old success receipt. A crash before/after the journal commit is inspected against actual Git content; an unknown merge is not automatically retried. No cleanup resets, forced checkout, stash, or implicit master push is performed.

Source freshness and target samples must be rechecked after synchronization, including when master advances during/after the merge. A recorded merge is not permission to apply comments, successful quality assessment or human acceptance. Native providers and decision writers remain incomplete. Tests use actual temporary Git repositories, not live forge credentials or project-branch merges.

## Conditional Git publication

`review_publish.prepare(feature, gist, repository, binding, observation, draft, authority_source_ref, authority=True)` accepts an explicitly authorized, canonical full review document. It verifies the registered source and actual observation, retains existing RV IDs, and rejects implicit deletion or noncanonical/legacy drafts. Legacy conversion must first be explicitly previewed using the codec; the host must authorize the actual proposed document. The full draft, original source, changed RV records and immutable candidate commit are retained in a tracked, declared F03 `review-publish` intent. Preparation never pushes. It returns an operation ID and an intent digest: the trusted host retains this digest independently as the scope of its authorization. The digest is not authentication and must not be minted from an untrusted journal to manufacture permission.

`execute(..., authority=True, expected_intent_digest=host_retained_digest)` checks the retained scope and current context. In a private bare repository it reproduces the exact candidate: sole parent is the observed remote master; the tree changes only the bound review document. It never checks out or pushes the working branch. The dispatch marker is persisted before a push with an explicit exact-old-SHA lease. This is a conditional fast-forward, not a history rewrite. Git commit identity comes from the configured host repository; private transport setup still requires actual host authentication. Each Git subprocess is bounded to 50 seconds, input/output to 4 MiB, and the complete F03 intent to 4 MiB; commit metadata is additionally bounded to 16 KiB. No credentials belong in bindings, drafts, or logs.

On a changed source the result reports `publication_status=conflict` and `http_status=409`, retaining the draft by its intent reference. A conflict stops that attempt permanently, even if master later returns to the old SHA. Unknown outcomes query the same actual RV UUIDs and compare their complete records; neither execute nor reconcile automatically reposts. `present` proves current readback, not a receipt of the original call. F03 `effect` describes journal updates, not remote publication success. `agent_consumed=false` and `decision_effect=NONE` remain explicit. Read-only reconciliation never writes.

After new authorization and fresh source observation, `prepare(..., supersedes=old_operation_id)` permits a new attempt only after actual conflict readback. Old intent/draft and RV UUIDs remain; changed identities or an uncertain unchanged-source effect cannot bypass recovery. Management journal checkpoints may advance by ancestry with the same read set; implementation HEAD changes stop the operation. The review_workflow caller exists; current host permission/credentials are runtime dependencies, decision/quality use separate routes and UI is optional. Bare-remote tests do not prove live forge access.

## Native raw-document transport

### Journaled publication

`review_native_publish.prepare(feature, gist, endpoint, observation, draft, authority_source_ref, authority=True)` persists the complete original, canonical draft, changed RV records, actual native version and feature/repository read set in a declared F03 gist. The returned intent digest must be retained independently by the host as the exact approved scope, not inferred from the journal on restart. The host supplies the configured endpoint independently; the journal contains its non-secret identities and URL digest, never its URL or credential headers. A digest does not authenticate a host or provider.

`execute(..., endpoint, authority=True, expected_intent_digest=...)` verifies scope, binding, feature context and actual source. It saves dispatch before a single conditional PUT. On response loss or reentry, it reads the same RV UUIDs and compares complete records without resending. An observed version/content conflict, including HTTP 409/412, permanently stops that attempt; the full draft remains in the intent. An unavailable readback remains unknown. `present` proves the records exist now, not who wrote them or whether the original call returned successfully. No result changes task decisions, quality, acceptance or agent consumption.

An explicit newly authorized `prepare(..., supersedes=old_id)` is permitted only after actual conflict observation, with retained RV identities and old draft. The retired attempt can no longer execute. Unchanged-source unknown attempts cannot be bypassed with new intents. `task_operation.reconcile(..., native_endpoint=endpoint)` supports read-only lookup or authorized journal-only recording; absent/mismatched host bindings fail closed, never resolve an endpoint from untrusted persisted content. A management checkpoint may advance while the retained read set is unchanged. Implementation HEAD movement still requires recovery. Tests combine real temporary Git journals and local HTTP, including abrupt process exit after the remote write; live host/provider authentication and UI workflow integration are separate requirements.

`review_native.NativeDocument` is a host-configured UTF-8 raw-document endpoint, not an adapter for arbitrary provider JSON APIs. Bind only an existing endpoint that implements strong conditional writes. Its GET returns the actual single strong ETag as a native version, original text and SHA-256 content digest; the digest is not a provider version. `If-Match` uses strong comparison and a failed condition prevents the requested change, as specified by [RFC 9110, section 13.1.1](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.1). Weak/missing/multiple ETags are refused, never replaced by a fabricated Git SHA or wildcard.

The host independently binds provider/source/feature/review identities, HTTPS URL and credentials. They must not come from review text. URLs containing user information, query strings, fragments or controls are refused; API credentials belong in host-owned headers, never journals or logs. Redirects are not followed. Tests may explicitly enable HTTP on literal loopback addresses only. The adapter accepts text/plain or text/markdown UTF-8 identity representations up to 4 MiB. A separate spawned worker bounds each request (connect at most 3 seconds, read at most 10, total at most 15 including cleanup reserve); there is no polling or automatic retry. Error diagnostics are redacted codes. Local HTTP fixtures do not establish real provider identity or permissions.

`read_for_purpose` has the same foreground/default-PENDING/explicit-ID behavior as Git reading. An absent binding is empty; an existing binding returning 404, denied access, redirection or transport error is not empty. `conditional_put(text, actual_condition, authority=True)` sends one PUT. A 200/204 response is `acknowledged`, not verified readback; 409/412 is normalized to conflict/409; other or lost responses are unknown. It always reports `draft_persisted=false`, `agent_consumed=false`, `decision_effect=NONE`. The caller retains responsibility for the draft. This low-level method is not an alternative publication workflow: use the journaled native publisher above for durable intent, dispatch marker, same-UUID readback and conflict/new-attempt policy; review_workflow already supplies the composed Skill-only caller; actual endpoint/authentication is host configuration and UI is optional. Do not invoke it as an unjournaled workaround.
