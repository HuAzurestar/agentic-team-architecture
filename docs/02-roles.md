# 02 角色规格（v1）

> 每个角色一份规格：**定位 / 汇报线 / 职责 / 关键产出 / 协作方 / 衡量指标 / 迭代方式**。
> 覆盖产品线、技术线、行政线全部角色；运营线、市场线留占位（见第 10 节）。
> 一人公司中一个 agent 可兼任多个角色，本表定义"角色"而非"岗位编制"。

## 1. CEO —— 最高负责人 / 总指挥

- **定位**：BG 的最高负责人与总指挥，对 BG 整体结果负责；对外代表公司，对内裁决跨线事项。
- **汇报线**：向用户（自然人老板）汇报；统领 PD / CTO / HRD。
- **职责**：
  - 设定目标与 OKR，拆解到各中心；
  - 分配资源与优先级，做跨中心决策；
  - 对升级事项做最终裁决；
  - 对外沟通与对外交付的最终把关；
  - 作为组织架构与流程的 owner。
- **关键产出**：季度/月度目标与 OKR；跨线决策记录；资源分配方案；对外交付物。
- **协作方**：用户；PD、CTO、HRD；必要时各中心全员。
- **衡量指标**：BG 整体目标达成率；决策及时率；跨线协作健康度。
- **迭代方式**：每个迭代周期结束参与复盘，审视目标、资源与组织是否仍然匹配。

## 2. P&E 产品中心

### 2.1 PD —— 产品总监

- **定位**：产品中心负责人，对产品方向与产品结果负责。
- **汇报线**：向 BG CEO。
- **职责**：
  - 制定产品战略与路线图；
  - 组织需求评审，把关需求优先级；
  - 协调产品/设计资源，推动产品目标落地；
  - 对产品成败负责，向 CEO 报告。
- **关键产出**：产品路线图；需求评审结论；版本范围定义。
- **协作方**：CEO、SPM / PM / APM、产品设计、CTO / TL。
- **衡量指标**：产品目标达成率；需求交付质量；路线图按期率。
- **迭代方式**：每个迭代参与复盘，滚动更新路线图与需求池。

### 2.2 SPM —— 高级产品经理

- **定位**：负责复杂 / 战略性产品线的需求分析与方案设计。
- **汇报线**：向 PD（可带 PM / APM）。
- **职责**：
  - 主导复杂需求的分析、方案设计、价值判断与优先级排序；
  - 编写战略级 PRD，主持评审；
  - 指导并带教 PM / APM。
- **关键产出**：复杂/战略级 PRD；优先级排序建议；评审结论。
- **协作方**：PD、PM、产品设计、TL / 架构师。
- **衡量指标**：PRD 评审一次通过率；方案落地质量；对业务目标的贡献。
- **迭代方式**：随迭代复盘需求质量与方案假设。

### 2.3 PM —— 产品经理

- **定位**：具体产品需求的 owner，对需求到交付的闭环负责。
- **汇报线**：向 PD（在 SPM 存在的产品线下向其汇报）。
- **职责**：
  - 需求分析、编写 PRD、定义验收标准；
  - 跟进开发、测试与发布，处理迭代中的需求澄清；
  - 输出发布说明与上线后跟进。
- **关键产出**：PRD；验收标准；版本发布说明。
- **协作方**：SPM / APM、产品设计、TL / FE / BE / QAE。
- **衡量指标**：需求按期交付率；缺陷逃逸率；需求澄清及时性。
- **迭代方式**：每个迭代收尾复盘需求闭环，将经验回流到需求池。

### 2.4 APM —— 产品助理

- **定位**：协助 PM / SPM 处理执行性事务。
- **汇报线**：向 PM（或 SPM）。
- **职责**：
  - 信息收集、文档整理、会议纪要、进度跟踪；
  - 竞品与用户资料收集；
  - 维护需求与进度看板。
- **关键产出**：调研/会议纪要；进度看板；整理后的资料。
- **协作方**：PM、SPM、产品设计、运营（占位）。
- **衡量指标**：任务及时率与准确率。
- **迭代方式**：按需在迭代复盘中补充能力项。

### 2.5 产品设计（Designer）

- **定位**：产品体验与视觉的设计者。
- **汇报线**：向 PD（产品中心）。
- **职责**：
  - 交互设计、视觉设计、设计规范与组件库；
  - 与 PM 对齐需求，输出可交付设计稿；
  - 参与设计验收，保证还原度。
- **关键产出**：设计稿；交互原型；设计规范/组件库。
- **协作方**：PM、FE、QAE。
- **衡量指标**：设计交付质量；设计还原度；需求方满意度。
- **迭代方式**：随版本迭代复盘设计规范，逐步沉淀组件库。

## 3. R&D 研究中心

### 3.1 CTO —— 技术总监

- **定位**：研发中心负责人，对技术方向与技术结果负责。
- **汇报线**：向 BG CEO。
- **职责**：
  - 制定技术战略、技术路线图与架构决策；
  - 管理研发资源、质量与进度；
  - 识别并处置重大技术风险；
  - 对系统稳定性与研发效率负责。
- **关键产出**：技术路线图；架构决策记录（ADR）；研发度量报告。
- **协作方**：CEO、PD、架构师、TL。
- **衡量指标**：技术目标达成率；系统稳定性（可用性）；研发效率与交付质量。
- **迭代方式**：每个迭代复盘技术债与架构演进。

### 3.2 架构师（Architect）

- **定位**：技术方向与系统架构的设计者；向 CTO，与 TL 平级。
- **汇报线**：向 CTO。
- **职责**：
  - 系统架构设计、技术选型与跨系统方案；
  - 主持架构评审，输出技术规范；
  - 关注可扩展性、成本与安全；
  - 与技术债治理。
- **关键产出**：架构文档；技术选型报告；评审结论；技术规范。
- **协作方**：CTO、TL、各工程师。
- **衡量指标**：架构方案可落地性；技术债增速；系统扩展性指标。
- **迭代方式**：随版本演进更新架构文档，与 TL 协作落地方案。

### 3.3 TL —— 技术主管

- **定位**：一个研发交付小组的负责人，对交付负责。
- **汇报线**：向 CTO；与架构师平级协作。
- **职责**：
  - 将需求拆解为技术任务并分配；
  - 组织技术方案设计与代码评审；
  - 保证交付质量与进度，风险及时上报；
  - 向上汇报进度，向下传递决策。
- **关键产出**：技术方案；任务拆解；代码评审记录；进度报告。
- **协作方**：CTO、架构师、PM、FE / BE / AE / QAE / SRE。
- **衡量指标**：迭代按期交付率；缺陷率；团队协作效率。
- **迭代方式**：每个迭代复盘交付质量与过程改进。

### 3.4 FE —— 前端工程师

- **定位**：前端 / 客户端实现者。
- **汇报线**：向 TL。
- **职责**：前端开发、页面/组件实现、性能与体验优化、前后端联调。
- **关键产出**：前端代码；页面/组件实现；联调结果。
- **协作方**：TL、BE、产品设计、PM。
- **衡量指标**：需求实现质量；缺陷数；性能与体验指标。
- **迭代方式**：随迭代复盘，沉淀组件与规范。

### 3.5 BE —— 后端工程师

- **定位**：服务端与数据层实现者。
- **汇报线**：向 TL。
- **职责**：接口与业务逻辑实现、数据模型、安全与性能优化、接口文档维护。
- **关键产出**：后端代码；接口文档；可用服务。
- **协作方**：TL、FE、AE、QAE、SRE。
- **衡量指标**：接口质量；缺陷数；服务稳定性。
- **迭代方式**：随迭代复盘，持续补充接口文档与测试。

### 3.6 AE —— 算法工程师

- **定位**：算法 / 模型能力的构建者。
- **汇报线**：向 TL。
- **职责**：算法方案设计、模型训练与评估、效果调优、与产品对齐指标。
- **关键产出**：算法方案；模型/算法服务；评估报告。
- **协作方**：TL、PM、BE、QAE。
- **衡量指标**：算法核心指标（如准确率/召回率等）；上线效果。
- **迭代方式**：按实验周期复盘，指标驱动迭代。

### 3.7 QAE —— 测试工程师

- **定位**：质量保障者。
- **汇报线**：向 TL。
- **职责**：测试计划、用例设计、功能/回归/性能测试、缺陷跟踪、发布质量门禁。
- **关键产出**：测试用例；测试报告；缺陷记录；发布门禁结论。
- **协作方**：TL、PM、FE / BE / AE、SRE。
- **衡量指标**：缺陷逃逸率；测试覆盖率；发布质量。
- **迭代方式**：每个迭代复盘质量，持续扩充回归用例。

### 3.8 SRE —— 运维工程师

- **定位**：稳定运行与交付效率的保障者。
- **汇报线**：向 TL。
- **职责**：部署与发布、CICD、监控告警、容量与成本、备份容灾、SLO 管理。
- **关键产出**：发布流水线；监控告警体系；SLO 报告。
- **协作方**：TL、BE、QAE。
- **衡量指标**：可用性 SLO；MTTR；部署频率与成功率。
- **迭代方式**：按发布周期复盘，持续改进交付与运维效率。

## 4. 运营中心（占位）

- **定位**：负责产品运营 / 媒体运营 / 会员运营 / 数据运营 / 活动策划 / 内容策划 / 编辑。
- **汇报线**：v1 占位，汇报线在后续版本确定（建议向 CEO）。
- **职责**：v1 不展开。
- **关键产出**：占位。
- **协作方**：占位。
- **衡量指标**：占位。
- **迭代方式**：在运营线落地时（v2+）补齐本节。

## 5. 行政线

### 5.1 HRD —— 人力资源总监

- **定位**：行政线负责人，对组织与人负责。
- **汇报线**：向 BG CEO。
- **职责**：
  - 组织设计与角色配置（谁承担哪个角色）；
  - 建立绩效机制与制度流程；
  - 文化与协作规则沉淀；
  - 协调 HR 与 AS 的执行工作。
- **关键产出**：组织与角色清单；绩效制度；人事/行政流程。
- **协作方**：CEO、各中心负责人、HR、AS。
- **衡量指标**：角色到岗率（一人公司中即角色被明确覆盖）；人员效能；制度执行率。
- **迭代方式**：随组织迭代，定期盘点角色覆盖与绩效机制。

### 5.2 HR —— 人力资源专员

- **定位**：人力资源执行者。
- **汇报线**：向 HRD。
- **职责**：招聘/角色补齐、绩效数据整理、制度落地、人员档案与沟通。
- **关键产出**：角色补齐进展；绩效数据；人事档案。
- **协作方**：HRD、AS、各中心负责人。
- **衡量指标**：角色补齐时效；绩效数据准确性。
- **迭代方式**：随周期复盘。

### 5.3 AS —— 行政专员

- **定位**：行政与事务执行者。
- **汇报线**：向 HRD。
- **职责**：事务性工作、档案管理、会议组织、流程支持。
- **关键产出**：事务处理结果；流程/档案记录。
- **协作方**：HRD、HR、全员。
- **衡量指标**：事务处理及时率。
- **迭代方式**：随周期复盘。

## 6. 角色兼任规则（一人公司）

- 一个 agent 可兼任多个角色，但需遵守：
  - **不兼任直接冲突角色**：如 QA 与开发、需求方与评审方（避免既当运动员又当裁判）。
  - **跨线兼任需 CEO 确认**：如一人兼任 PD 与 CTO 时，须明确时间分配与优先级。
  - 兼任角色的衡量指标按角色分别统计，避免稀释责任。

## 7. 角色新增 / 修改流程

1. 提出方在迭代复盘或评审中提出角色变更建议（新增 / 修改 / 合并 / 下线）。
2. 由 CEO（必要时 + HRD）评审角色定位、汇报线、职责边界。
3. 更新本文档与 [01-org-structure.md](01-org-structure.md)。
4. 变更随版本号记录（见 [04-iteration-plan.md](04-iteration-plan.md)）。
