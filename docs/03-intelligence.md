# 03 大小智能管理（v2）

> 让**任务复杂度**与**模型成本档位**匹配。大小智能管理 = 三级分级：**Assist（助理）/ 普通（标准）/ Senior（高级）**——每一级对应一档模型成本。避免"成本爆炸而收益式微"。

## 1. 目标

- **不浪费**：例行、确定性的任务用最低成本档（Assist）即可，不必调用高成本模型。
- **不掉链**：复杂、高风险的决策必须由足够强的模型（Senior）承担。
- **可度量**：每个 Agent 的档位 = 其模型成本档位，成本与质量可预期。

## 2. 三级分级（= 模型成本档位）

| 档位 | 级别 | 模型定位 | 成本特征 | 适用任务 |
| --- | --- | --- | --- | --- |
| Assist | 助理 | 最便宜的模型 | **以 free 为目的** | 例行、结构化、低风险（格式化、检索、简单问答、日志整理） |
| 普通 | 标准 | 初级生产模型 | **有一定价格，频繁使用可以承受** | 一般业务任务、常规执行（常规编码、文档撰写、流程执行） |
| Senior | 高级 | 高级生产模型 | **价格极高，频繁使用无法承受** | 复杂决策、策略、高影响（架构决策、产品成色、跨线裁决、复杂推理） |

> 三级分级与 [01-org-structure.md](01-org-structure.md) §5 的命名规则（级别三级：Senior / - / Assist）一致：一个 Agent 的"级别"就是它挂载的模型成本档位。

## 3. 智能管理归属：HR × 部门管理者

大小智能管理是 **HR 与所有负责派发任务的职能（部门管理者）** 的共同职责：

- **HR（成本与配置台账）**：
  - 负责记录不同的 **模型、Agent Program、CLI 参数配置** 等可能带来的**时间成本、用工成本**；
  - 维护"哪个档位 = 哪种模型/程序/配置、单位成本多少"的台账；
  - 为派发任务提供成本基准。
- **部门管理者（C..O / 各线负责人，能力与模型适配）**：
  - 需要了解**下属职员擅长什么、不擅长什么**；
  - 了解**适合什么模型、不适合什么模型**；
  - 为派发任务提供能力依据。
- **结合派发**：HR 提供成本/配置基准，部门管理者提供能力/适配判断——两者结合，才能**准确派发任务**，避免成本爆炸而收益式微。

## 4. 任务 ↔ 档位匹配

- 任务进入时先**分级**：例行 → 常规 → 复杂/高影响。
- 例行任务默认派给 **Assist** 档 Agent（低成本模型 + 专项 Skill），产出质量由 Skill/模板保障。
- 常规任务派给 **普通** 档 Agent。
- 复杂/高影响任务派给 **Senior** 档 Agent，必要时挂载 MCP/Hook 获取外部能力。
- 同一角色可拥有多档 Agent：日常执行用低档，关键时刻切换到高档。

## 5. 组合与挂载

- **Agent 规格 = Agent Program + 模型档位 + Skill +（MCP / Hook）**。
- 低档 Agent 通过**更细的 Skill 与流程**弥补模型能力（把不确定性锁在流程里）。
- 高档 Agent 用于**高不确定、高影响**的环节，减少对流程的依赖。
- 成本控制：按任务实际复杂度动态选档，避免一律上大模型。

## 6. 衡量

- **质量**：各档任务的成功率/缺陷率，验证分档是否合理。
- **成本**：单位任务的模型调用成本（HR 台账），用于迭代调档。
- **效率**：例行任务的处理耗时，低档 Agent 应显著更快。

> 台账的具体参数（哪些任务归哪档、用哪个模型/程序/CLI 配置、单位成本）由 HR 记录，配合各 C..O 维护（见 [docs/02-boundaries.md](02-boundaries.md)）。
