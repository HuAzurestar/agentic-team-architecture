# 03 大小智能管理（v2）

> 让**任务复杂度**与**模型/Agent 规格**匹配：小/快模型跑例行任务，大模型做复杂决策，兼顾成本与质量。

> 说明：本节为 v2 的框架性定义。若对"大小智能管理"有不同理解，请指正，据此调整。

## 1. 目标

- **不浪费**：例行、确定性的任务用低规格模型即可，不必调用大模型。
- **不掉链**：复杂、高风险的决策必须由足够强的模型/Agent 承担。
- **可度量**：每个角色/任务都有明确的"智能等级"档位，成本与质量可预期。

## 2. 智能分档

| 档位 | 规格 | 适用任务 | 示例 LLM | 说明 |
| --- | --- | --- | --- | --- |
| S | 小/快模型 | 例行、结构化、低风险 | 轻量/快速模型 | 格式化、检索、简单问答、日志整理 |
| M | 中型模型 | 一般业务任务、常规执行 | 中档模型 | 常规编码、文档撰写、流程执行 |
| L | 大/强模型 | 复杂决策、策略、高影响 | deepseek / GLM / GPT / claude 等强模型 | 架构决策、产品成色、跨线裁决、复杂推理 |

## 3. 任务 ↔ 智能匹配

- 任务进入时先**分级**：例行 → 常规 → 复杂/高影响。
- 例行任务默认交给 S 档 Agent（小模型 + 专项 Skill），产出质量由 Skill/模板保障。
- 复杂决策默认交给 L 档 Agent（大模型），必要时挂载 MCP/Hook 获取外部能力。
- 同一角色可拥有多档 Agent：日常执行用低档，关键时刻切换到高档。

## 4. 组合与挂载

- **Agent 规格 = Agent Program + LLM 档位 + Skill +（MCP / Hook）**。
- 低档 Agent 通过**更细的 Skill 与流程**弥补模型能力（把不确定性锁在流程里）。
- 高档 Agent 用于**高不确定、高影响**的环节，减少对流程的依赖。
- 成本控制：按任务实际复杂度动态选档，避免一律上大模型。

## 5. 衡量

- **质量**：各档任务的成功率/缺陷率，验证分档是否合理。
- **成本**：单位任务的模型调用成本，用于迭代调档。
- **效率**：例行任务的处理耗时，低档 Agent 应显著更快。

> 分档的具体参数（哪些任务归哪档、用哪个模型）在运行中由 HR Nexus 协同各 C..O 维护（见 [docs/02-boundaries.md](02-boundaries.md)）。
