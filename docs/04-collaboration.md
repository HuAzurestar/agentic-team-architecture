# 04 协作模式（v2）

> 产品 / 技术 / 运营 / 人事 / 行政之间的协作流与跨线协同。

## 1. 核心价值流

```
产品成色（CPO · PC 设计） → 技术实现（CTO · TC 交付） → 长期执行（COO · OC 运营） → 反馈回流
```

| 阶段 | Owner | 参与 | 关键动作 | 出口物 |
| --- | --- | --- | --- | --- |
| 成色设计 | CPO（PC 产品中心） | CTO、COO、AS | 定义产品成色、需求、验收标准 | 产品定义 + 验收标准 |
| 技术实现 | CTO（TC 技术中心） | CPO、COO | 技术方案、研发实现、交付 | 可运行的实现 |
| 长期执行 | COO（OC 运营中心） | CPO、CTO | 运营执行、增长留存、执行闭环 | 运营数据 + 执行记录 |
| 反馈回流 | 各中心 | 个人、AS | 用户/数据/缺陷反馈回流，进入下一轮 | 反馈汇总 → 迭代输入 |

### 交接规则

- **成色设计 → 技术实现**：CPO 交付"要什么"（定义 + 验收），CTO 决定"怎么做"。
- **技术实现 → 长期执行**：CTO 交付可用实现，COO 接手运营执行。
- **全程推进**：AS 推动各阶段按计划进行（**限于 CEO 已确认的事项**），跨线阻塞由 AS 督办并上报 CEO 确认。
- **人事配置**：HR 在变更发生时调整 agent 归属与 skill 配置（如某个阶段需要更强模型/更多 Skill）。

## 2. 跨线协同

- **产品 × 技术**：CPO 定义成色，CTO 实现；边界冲突（如"成本 vs 质量"）由双方协商，不成升级。
- **技术 × 运营**：CTO 保证可运行与稳定，COO 负责执行与增长；线上问题按严重级联动处理。
- **产品 × 运营**：CPO 定成色基准，COO 在基准内做长期执行；运营反馈回流给 CPO 调整成色。
- **人事 × 各线**：HR 负责 agent 归属、skill 配置；配置变更需通知受影响线负责人。
- **行政（AS）× 各线**：AS 推动进度、处理杂务；不替代业务决策。

## 3. 升级机制

1. 相关 C..O 协商 → 2. AS 推动协调（限于 CEO 已确认范围内）→ 3. **CEO（个人/自然人）最终确认**。
- 越权（红线）即升级为事故，立即纠正并复盘。
- 升级必备信息：问题、影响、已尝试方案、需要的决策。

## 4. 例行同步

| 活动 | 频率 | 参与者 | 目的 |
| --- | --- | --- | --- |
| 规划对齐 | 每迭代开始 | 各线 | 对齐范围与优先级 |
| 站会/进度同步 | 每日或按需 | 各线 + AS | 同步进度、暴露阻塞 |
| 评审 | 迭代中 | 相关线 | 评审关键交付物 |
| 复盘 | 迭代结束 | 全员 | 结果复盘 + 改进项 |

> 迭代节奏与复盘机制见 [docs/05-iteration.md](05-iteration.md)。
