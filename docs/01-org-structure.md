# 01 组织架构（v1）

> 本文档定义 agentic team 的组织架构树，以及 BG / BU / R&D / P&E 等核心概念。版本：**v1**（见 [04-iteration-plan.md](04-iteration-plan.md) 的版本演进规则）。

## 1. 核心概念

| 概念 | 全称 | 说明 |
| --- | --- | --- |
| OPC | ONE PERSON COMPANY | 一人公司形态：一个自然人通过一组 agent 运营公司 |
| BG | 事业群 | 本架构的**基准组织单元**；v1 以单一 BG 为 POC（proof of concept） |
| BU | 事业部 | 跨产品线的**矩阵单元**（产品 + 技术组合）；v1 仅作为占位概念写入，不展开 |
| P&E | 产品中心 | 产品与体验（Product & Experience），负责产品方向与需求 |
| R&D | 研究中心 | 研发（Research & Development），负责技术方向与交付 |
| 运营中心 | —— | 产品运营 / 媒体运营 / 会员运营 / 数据运营 / 活动策划 / 内容策划 / 编辑；**v1 占位** |
| 行政线 | —— | 组织与人、事务支持：HRD / HR / AS |

## 2. 组织架构树（v1）

```
BG 事业群（POC）
├── CEO（最高负责人/总指挥）
│
├── P&E 产品中心 —— PD 产品总监
│   ├── SPM 高级产品经理
│   ├── PM 产品经理
│   ├── APM 产品助理
│   └── 产品设计（Designer）
│
├── R&D 研究中心 —— CTO 技术总监
│   ├── 架构师（Architect，向 CTO，与 TL 平级）
│   └── TL 技术主管
│       ├── FE 前端工程师
│       ├── BE 后端工程师
│       ├── AE 算法工程师
│       ├── QAE 测试工程师
│       └── SRE 运维工程师
│
├── 运营中心（占位，v1 先不管）——产品运营 / 媒体运营 / 会员运营 / 数据运营 / 活动策划 / 内容策划 / 编辑
│
└── 行政线 —— HRD 人力资源总监
    ├── HR
    └── AS 行政专员
```

## 3. 汇报线

| 上级 | 下级 | 说明 |
| --- | --- | --- |
| BG CEO | PD / CTO / HRD | 各中心负责人直接向 CEO 汇报 |
| PD | SPM / PM / APM / 产品设计 | 产品中心内部 |
| CTO | 架构师 / TL | 架构师与 TL 平级，均向 CTO |
| TL | FE / BE / AE / QAE / SRE | 研发交付小组 |
| HRD | HR / AS | 行政线 |
| —— | 运营线 / 市场线 | v1 占位，后续迭代补齐 |

## 4. BG 与 BU 的关系

- **BG** 是纵向的**业务组织单元**，对业务结果负责，是 v1 的基准（POC）。
- **BU** 是横向的**矩阵单元**，由跨产品线的**产品 + 技术**组合而成，用于支撑一个具体产品线或项目，资源来自 P&E 与 R&D。
- v1 先把 BU 作为占位概念写入文档、不展开；等 POC 跑通后再在后续版本（v2+）定义 BU 的组建方式、汇报线与绩效归属。

## 5. 扩展与复制

- 多 BG：以 v1 单一 BG 为模板复制，每个 BG 内部结构相同，各 BG 之间通过 CEO（或未来新增的集团层）协调。
- 多 BU：在 BG 内部按产品线划分 BU，P&E 与 R&D 人员以矩阵方式加入。
- 角色数量可收缩：一个 agent 可兼任多个角色（一人公司中这是常态），本架构只定义"角色/职责"，不规定"必须一人一角"。
