# 工作流 08：研究交付物审核与升级

> RC 研究交付物的统一审核口与升级机制（2026-08-13 CEO 指令落地）。所有研究交付物提交 in_review 前必须经手**审核专员**审核；数学家 / 算法研究员交付物审核 1 次不通过 → 升级 **数学&算法专员·Senior** 处理。

## 目的

把「研究交付物 → 审核专员审核 → 升级 Senior」固定成流程：统一审核口径（五维审计）、作者与审核专员互斥（不得自审自放行）、难题自动升级到更高档位模型处理，保证研究交付质量与效率。

## 触发

- 数学家 / 算法研究员 / 研究助理完成研究交付物（代码 / 实验 / 论文 / 文章 / Lean 证明），准备提交 in_review。
- 审核专员审核判定 1 次不通过。

## 步骤

1. **提交审核**：作者完成交付物后，提交 in_review 前先经手 **审核专员**（claude code / dsv4p，挂最先进审核 skill：`research-review` / `open-code-review` / `lean4-theorem-proving` / `algorithm-solver` / `doc-review-2` 等）。**作者与审核专员互斥，不得自审自放行**。
2. **审核**：审核专员按**五维审计**审查（引文存在性 / 内容可追溯性 / 判断准确性 / 计划合理性 / 失败备案充分性，与既有审计条件一致）；审核记录落 issue。
3. **通过**：审核通过 → 交付物进入 in_review，由 CRO 收口推进。
4. **升级**：数学家 / 算法研究员交付物审核 **1 次不通过** → CRO 升级派发给 **数学&算法专员·Senior**（claude code / dsv4p，知晓数学和算法一切细节含 skill）代为处理，后续由 Senior 持续推进至通过。
5. **回填**：审核中发现的共性问题回填审查 skill（CKO 整理），使工具随研究进化。

## 出口物

- 审核通过的交付物（进入 in_review）+ 审核记录（落 issue）。
- 升级任务的处理记录（Senior 持续至通过）。

## 负责角色

- **作者**：数学家 / 算法研究员 / 研究助理（提交交付物）。
- **审核专员**：统一审核口（不代写成果，只审核）。
- **数学&算法专员·Senior**：处理升级任务。
- **CRO**：全权调度 RC 内部，指派审核与升级派发。
- **CKO**：审核共性问题回填审查 skill。
