# 工作流 05：核心价值流（PC 设计 → TC 实现 → OC 运营）

> 产品开发运营 BG 的核心总流程，**CEO 视角下不可改**；产品由 CEO 下发或确认创建，**AS 跟进推进**。

## 目的

把「成色设计 → 技术实现 → 长期执行」的交接固定下来，下游可驳回、严重问题升级开会。

## 触发

- CEO 下发 / 确认一个产品需求。

## 步骤

1. **成色设计（CPO / PC）**：定义产品成色、需求、验收标准 → 出口：产品定义 + 验收标准。
2. **技术实现（CTO / TC）**：技术方案、研发实现、交付 → 出口：可运行的实现。
3. **长期执行（COO / OC）**：运营执行、增长留存、完整落地 → 出口：运营数据 + 执行记录。
4. **反馈回流**：用户 / 数据 / 缺陷反馈回流，进入下一轮 → 迭代输入。

### 交接与例外

- 交接即**责任转移**：CPO 交付"要什么"，CTO 决定"怎么做"，COO 接手执行。
- **驳回机制**：下游发现问题可驳回上一流程重新处理。
- **严重问题升级**：职员搞不定 → 升级 → 高职能开会处置，决定产品去留。
- **中心内部全权**：中心内部如何运作（是否严格审核、重做还是驳回、是否启用高级职员）由主管（CPO / CTO / COO）全权决策，CEO 不干涉。

## 出口物

- 每阶段出口物 + 交接记录（落于 issue）。
- 跨中心阻塞由 AS 督办并上报 CEO 确认。

## 负责角色

- **CPO / CTO / COO**：各阶段 Owner。
- **AS**：全程推进（限于 CEO 已确认事项）。
- **HR**：变更时调整 agent 归属与 skill 配置。
