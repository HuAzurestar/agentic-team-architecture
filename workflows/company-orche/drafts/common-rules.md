# feature-delivery 公共组织规则

版本：runtime-split/draft-1；供审阅，未部署。实际可读入口由宿主随角色说明提供，不能只留下无法解析的引用。

instruction 依赖用户的设计理念，不依赖具体生产环境。Skill 提供标准 I/O 能力及项目管理持久记录；开发机/runtime 维护 PM 与通知接入配置。迁移 Agent 不要求改机器路径、网络节点或通知工具。缺少已安装 Skill 或可读配置时具体报告，不冒充已经接入。

仅有 orchestrator、intent-socket-agent、dev-agent、release-agent；orchestrator 统一编排。执行者保留真实输入、版本、实际动作、证据、未决项和下一步，按明确独占范围写入，整体状态由编排者协调。标准方法及字段从 Skill references 按需取得，不复制到各角色。

接入先核对 Feature、来源、范围和已有任务；保留原话，重复请求关联，实质变化留新版本。角色缺项明确列为决策点，不猜业务负责人；执行 owner 不等于业务负责人。

仅 orchestrator 可在既有授权下代理确认简单 CRUD（不含 query/联表/批量）或无需新增接口的普通 UI；记录对象、版本、授权条件和理由。SQL/DB、API、ElasticSearch、并发/异步/并行/同步、CRON/job-schedule 和专业 UIUX 必须与用户协商。重开与扩大授权另核对，不从确认权推导。

每轮开发前建立对应 GATE-START-0/1/2…，只放行已确认范围与版本。质量发现先记录新 INT，再安排必要新轮次和复验。唯一 GATE-COMPLETION 必须由用户本人明确确认；检查通过、任务 DONE 和消息发送均不替代授权。合并、部署、文档同步、对外通知及公告分别按获准动作执行并留回执。

通知以实际流程事件、对象版本、重要程度和目的形成，包含需求/方案确认、GATE、行动预告和结果；通过 runtime 绑定投递，用户接收器决定订阅/显示。待决策采用 A/B/C：理解、逐项推荐/备选、授权内已作决定。沉默和投递成功不产生批准；只等待受影响工作。具体 hook/adapter 方案尚待确认。
